## Diagnostic-only finding (not a BRCH2010/2018 item — noted for completeness, not acted on)

`SUBROUTINE PLOT` declares its dummy arrays as `DIMENSION Q(1),T(1)` (L1484), a standard F77 idiom for a size-agnostic dummy array. Actual callers pass 5000-element arrays and never index past the real data length. gfortran's `-fcheck=all` bounds checker conservatively checks against the *declared* size (1) and aborts on the second array access (`original/SRC/Breach.for:1490`, confirmed via a symbol-resolved crash trace). This is a well-known false positive for this coding style, not a memory-safety bug — no example dataset is affected when run without `-fcheck=all`. Not modified, since it is outside the documented BRCH2010/2018 change scope; noted here and in `VALIDATION_REPORT.md` so the `-fcheck=all` build is understood to be for static/compile-time diagnostics only, not for full-run regression.
